TL;DR：电网黑启动不是“让一群 agent 自由协作”，而是受安全约束、证据门控和人类调度权威约束的分层恢复工作流；通用 kernel 应可靠编排状态、权限、租约、审计与降级，而绝不能替代电力安全判据、潮流计算或调度命令。

# 电网黑启动与自愈：作为多 agent 协作系统的领域解剖

## 0. 分析边界与映射

- 此处的“agent”既包括自动控制器，也包括运行系统、现场执行单元和具法定调度权的人。
- 真实电力系统不是把 AI 直接接进断路器；保护装置和机组控制器有独立、硬实时的闭环。
- 因而 kernel 的调用对象应是受认证的“能力代理”：调度应用、EMS 功能、变电站网关、现场班组任务终端等。
- 黑启动是从全停或大面积失电开始，逐步形成带电孤岛、恢复厂用电和负荷，并最终同步并列的过程。[S1][S2]
- NERC EOP-005 要求负责恢复计划的实体具备并维护系统恢复计划，且计划须覆盖指定的黑启动资源。[S1]
- 每个区域/互联电网的预案、设备清单、调度权责和合规规则不同；下述是可泛化的机制，不是可直接执行的操作规程。
- 关键反例：不能将“并网”抽象成普通任务完成；它需要在断路器合闸前确认相角、频率、电压和设备能力。

## 1. 参与者/角色：异构、强权责、跨组织

- `System Operator / Reliability Coordinator`：决定恢复策略、孤岛边界、跨区联络线恢复和最终并网的调度权威。
- `Transmission Operator`：按预案操作输电开关、恢复走廊、控制无功/电压，并向调度报告线路与站内状态。
- `Balancing Authority`：在每个已成形岛内平衡发电与负荷、维持频率，并协调负荷块投入顺序。
- `Generator Operator`：启动黑启动机组或被黑启动电源带起的非黑启动机组，执行升速、励磁、并网和出力指令。
- 黑启动机组可为水电、燃机、柴油机或具有现场起动能力的资源；并非每台常规大型机组都能在全失电下自行起动。[S2][S3]
- `Plant DCS / governor / AVR`：毫秒至秒级局部控制 agent，分别调速、调频和调压；不等待中心 kernel 往返。
- `Protective relays / RAS(SPS)`：按本地量测跳闸或切负荷，目标是防止设备受损或失稳；它们是安全护栏而非可协商的任务参与者。[S4]
- `Substation IED/RTU/gateway`：把开关位、告警、模拟量上送，并可在授权范围内执行遥控；可因站用电、通信或时钟故障而退化。
- `EMS/SCADA`：汇总遥测、拓扑、告警和调度指令；黑启动期间它可能部分不可用，不能被视为唯一真相来源。[S5]
- `State estimator / contingency / power-flow tools`：对当前可观测网络给出估计、越限和恢复方案检查；停电后量测稀疏时置信度本身是输出。
- `Field crews`：核实现场设备状态、手动分合闸、排除损坏和补给燃料；在通信缺失时是高价值的“物理世界观测 agent”。
- `Distribution operator / microgrid controller / DER aggregator`：在配电网、微网或孤岛中实施本地恢复、负荷管理和可能的黑启动支撑。
- `Load-serving entity / critical-load liaison`：提供医院、供水、通信、核电厂等关键负荷的优先级和可投入条件。
- `Cybersecurity / telecom operator`：恢复专网、调度电话、卫星/无线备份和身份边界；通信恢复本身是关键任务。
- `Human incident commander`：在跨组织冲突、异常设备状态或计划外拓扑时作最终裁决。
- 数量级不是固定的“几个 agent”：一个控制区可有数十至数百站点/机组操作对象、数千 IED，跨互联区则是多个调度机构和成千上万设备。
- 异构性高：连续控制、离散开关、优化软件、人工审批和物理抢修具有不同的时钟、失败模式、权限与可验证性。

## 2. 通信：控制面不能依赖单一消息总线

- 控制中心—RTU/IED 通常通过 SCADA 遥测遥信遥控链路；站内自动化常用 IEC 61850，广域遥控还可见 DNP3、IEC 60870-5-101/104 等协议。[S5][S6]
- 这些协议承载的是带质量标志、时间戳和点号语义的工业数据，不是通用聊天文本。
- 调度员之间使用调度电话、语音录音、专线、无线或卫星备份；关键口头命令通常须复诵确认，作为低带宽但可工作的控制面。[S7]
- 调度中心向现场的操作是点对点、带对象地址的命令；“所有站点同时送电”的广播在物理上和流程上都不安全。
- 拓扑、恢复进度、约束与待办可表现为 EMS 共享状态或白板；但白板只是态势感知，不自动授予操作许可。
- 同一岛内频率、相角和电压是隐式的物理广播信号；机组调速器、AVR 和保护装置直接对其响应。
- 跨调度区的联络线恢复需要显式协调，而不是通过全局广播达成默认共识。
- 一个 kernel 的消息层应保留来源、对象、版本、时间戳、质量码、签名和确认状态，不能把测点扁平化成 JSON 值。
- 对“合闸”“起机”“投入负荷”这类命令，至少要支持命令—回执—遥信验证三阶段，而非以 API 200 视为成功。
- 在通信分区时，各孤岛可按预案本地运行；恢复后需执行状态对账，不能盲目重放离线命令。

## 3. 协调：预案优先的分层指挥，而非市场竞价

- 任务分配的主机制是事先批准的系统恢复计划、责任表和调度层级，而不是 agent 对任务公开竞价。[S1]
- 典型依赖链：黑启动电源可用 → 建立厂用/站用电 → 带起关键输电路径 → 恢复下一台机组 → 小块加载 → 扩展孤岛。
- 这是一张带硬前置条件的 DAG，但运行中会因设备故障、线路不可用和量测失真改写分支。
- 调度员/恢复指挥按计划选择黑启动路径；Transmission Operator 执行网络侧步骤；Generator Operator 执行厂侧步骤。
- 每一步应有明确“继续条件”：设备状态已证实、保护定值/运行方式匹配、潮流/无功余量可接受、通信与人员准备完毕。
- 频率低说明岛内负荷超过可用机械输入，必须拒绝或撤回后续加负荷；电压越限则可能需要调整无功、切除充电线路或改变拓扑。
- 多个区域都希望先恢复本地关键负荷时，裁决依据是恢复计划、可靠性协调职责、设备安全和互联稳定性，不是吞吐量最大化。
- 并列孤岛前由指定调度权威协调；同步检查合格只是技术门槛，合闸命令仍需拥有该开关控制权的实体执行。
- 自动化可以提出可行序列、检测未满足前置条件、阻断危险命令；它不应在计划外拓扑上自主重新定义安全边界。
- 通用 kernel 可实现“计划版本 + 依赖门 + 人工审批 + 仲裁记录”；领域应用须实现潮流、稳定、保护配合和具体预案规则。

## 4. 资源竞争：争的是可安全使用的电网能力

- 最稀缺的资源首先是可黑启动容量及其燃料、启动空气/电池、冷却水和现场人员，而非 CPU。
- 黑启动机组的容量既要供给自身和路径损耗，也要为下一机组的厂用电留出余量；同一资源不能被多个恢复路径过度承诺。
- 无功功率与电压控制能力是关键稀缺资源：轻载长线路会产生充电无功、造成过电压，变压器励磁也会引入浪涌风险。[S2][S8]
- 频率响应/旋转备用是每个孤岛的实时预算；投入一个大负荷块会消耗它，不能被异步任务各自“预订”。
- 线路、变压器、断路器和机组的热限额、操作次数、最小运行时间/爬坡速率约束了可并行程度。
- 电信带宽、调度电话通道、现场班组和关键备件会成为恢复早期的实际瓶颈。
- 关键负荷的“复电时间窗”也是冲突资源：医院、供水、通信和燃料管道可能各自有优先级和可带电条件。
- 调度方式不是普通队列：先锁定一个拓扑切换/送电走廊，再在完成遥信验证或租约过期前禁止冲突操作。
- 对可并行操作，kernel 可管理资源租约、容量声明和死锁检测；容量数值、潮流约束和优先级权重必须由电网应用提供。
- 必须支持撤销与补偿：若新带起机组失败，释放其预留的黑启动容量、工作票和路径锁，并重算后续步骤。

## 5. 失败与恢复：部分失效是常态，盲重试会扩大事故

- 黑启动机组可能因燃料、辅机、蓄电池、控制系统或机械故障无法启动；预案须有替代资源/路径。
- 线路送电可能遭遇故障、过电压、保护误动或开关拒动；不能无条件重复合闸。
- 变电站失去站用直流、通信或遥控时，会出现“命令未到”“命令已执行但回传丢失”“状态陈旧”三种不可混同的失败。
- EMS/SCADA 可能因供电、通信或网络攻击部分失效；运行人员应使用本地显示、调度电话和现场确认降级。[S5][S7]
- 量测缺失会让状态估计不可观测或置信度下降；kernel 必须显式传播 `unknown/stale/suspect`，禁止将缺失补成正常值。
- 保护装置或机组本地控制在上级通信失去后仍会动作；这是安全降级，不应被中心“恢复任务”覆盖。
- 同步失败、频率大幅偏移或相角不合格必须中止并列，保持岛间断开并重新稳态化；错误合闸可能触发设备损伤和再次解列。[S2]
- 检测来自遥信/遥测质量码、保护告警、通信心跳、复诵、现场见证及模型—实测残差的交叉验证。
- 恢复策略应区分：安全可重试（例如通知送达失败）、需人工确认后重试（开关状态未知）和永久/隔离（设备损坏）。
- 接管需以角色和权限为单位：主控制中心失效时，后备控制中心或本地站按预定切换；不可让任意在线 agent 抢占控制权。
- kernel 必须实现可持久化的 saga/补偿、超时与幂等键、租约失效、安全停止、健康心跳和明确交接；它不能定义继电保护动作逻辑。

## 6. 状态与真相：没有单一完美真相，只有带质量的操作事实

- EMS 通常维护网络模型、拓扑处理、SCADA 遥测和状态估计，是中心态势源，但停电时并不天然正确。[S5]
- 断路器实际位置、隔离开关位置、保护闭锁、机组转速/出力、母线电压和线路潮流是不同来源、不同刷新率的事实。
- 配网、输电和发电侧的模型可能版本不同；恢复时错误的拓扑模型会使“计划已完成”的判断完全错误。
- 对执行命令而言，真相优先级应是：有时间戳和质量码的现场遥信/现场见证 > 推断状态 > 计划状态。
- 对保护与控制，局部闭环需要毫秒级且强一致的本地量测；不能等待全网分布式共识。
- 对跨区恢复进度，可接受秒到分钟级最终一致，但每次跨边界操作需要强确认点和共同的模型/计划版本。
- 同步并网需要双方对联络点的实时量测、极性/相序及运行权限达成确认；“数据库最终一致”不够。
- 状态条目必须至少带：观测时刻、接收时刻、来源、质量、适用拓扑/计划版本、置信等级和操作者确认。
- kernel 可提供事件溯源、版本化快照、冲突检测、状态新鲜度 SLA 和对账协议。
- 应用层必须定义量测质量阈值、状态估计算法、设备语义以及“可继续”的电力安全判据。

## 7. 时间性：多时间尺度耦合，最危险动作有极短窗口

- 继电保护常在毫秒到周波级动作；调速器/AVR 的稳定控制在毫秒至秒级，必须位于 kernel 之外。[S4]
- SCADA 轮询、遥信传输和控制确认常在秒级；网络恢复与调度步骤多在分钟级。
- 黑启动机组起机、暖机、建立厂用电和带起大型火电机组可需分钟到小时；不能用单一短超时处理。[S2]
- 负荷恢复必须逐块、间隔观察频率/电压/潮流，而非所有下游任务一完成即并发执行。
- 同步检查和合闸是窗口化操作：量测足够新鲜、频率差/相角差/电压差在本地规程阈值内、双方均准备好时才发令。
- 恢复计划可异步推进；但一个岛内发电—负荷平衡和断路器操作顺序具有严格的串行栅栏。
- GPS/PTP 时钟异常会使事件排序、故障录波和跨站对账困难；要区分设备时间、接收时间和人工确认时间。
- kernel 应提供单调时钟、截止期/新鲜度检查、时间窗和不可延迟的升级告警；不能承担硬实时控制循环。

## 8. 人在环：人是授权与异常处置的控制回路

- 黑启动预案和责任分配在事前由合规/运行体系批准，运行时调度员按权限下达或确认关键操作。[S1]
- 调度员在不完整态势下选择恢复分支、批准越过自动建议的异常处理，并协调相邻控制区。
- 现场人员负责设备隔离、就地操作、验电/确认、燃料和损坏评估；这类物理确认不能由数字 agent 自证。
- 高风险点应使用双人复核或“命令复诵—确认—执行—状态回读”闭环，特别是线路送电、大发电机并网和孤岛同步。
- 自动控制以本地保护、调速和调压为主；人不应在事件瞬间手工替代这些闭环。
- 班次交接必须移交当前孤岛边界、已执行操作、未验证状态、设备故障、计划版本、权限租约和待决命令。
- kernel 可以生成可签名的交接包、阻止未授权高危执行、在超时升级到人；应用需决定谁可批准何种电网操作。

## 9. 观测与追责：需要能复盘“谁依据什么在何时改变了物理系统”

- 黑启动及演练要保留计划、训练/测试、通信和资源可用性的证据，以满足可靠性标准的合规要求。[S1]
- 控制中心应保留 SCADA 事件顺序记录（SOE）、告警、遥控命令、回执和语音调度录音；保护侧保留故障录波与继电器事件。[S4][S7]
- 复盘不能只看 workflow 日志：要把命令意图、授权人、设备返回、现场实际状态和频率/电压轨迹按时间关联。
- 每项命令应有不可变 correlation ID，关联计划步骤、操作者/agent 身份、目标设备点号、模型版本和双人复核证据。
- 必须记录未采纳建议、人工覆盖、自动阻断和超时接管，才能区分模型建议不佳、数据错误、通信延迟或人为决策。
- 事件时钟不一致时，审计系统须保留原始时间戳及其不确定度，而不是事后静默排序。
- kernel 可提供 append-only 审计事件、可查询因果链、审计导出、重放模拟和策略决策记录。
- 电力应用负责保存/解释波形、继保定值、机组数据和满足当地法规的保存期限。

## 10. 信任与权限：最小权限、双向认证、可撤销的操作控制权

- 调度中心、发电厂、输电业主、配电运营商和第三方通信方属于不同信任域，不能默认互信。
- 同一站内不同设备也有不同控制对象与操作权限；“看见遥测”不等于“可以分合闸”。
- 北美关键基础设施实践强调电子安全边界、身份认证、远程访问控制和日志，NERC CIP 为此设定强制可靠性要求。[S9]
- 对黑启动，权限还取决于操作状态：某一控制中心可在常态控制，宣布接管后后备中心才获得写权限。
- 并列操作常需两侧组织均确认；这是多方授权（two-man / two-party rule），不是单 token 的权限升级。
- 自动 agent 的能力 token 应细化到设备/动作/电压等级/有效时间窗/最大操作次数，并附带计划步骤和环境条件。
- 通信分区时应使用短租约与保守失效策略：过期后禁止新高危命令、维持已获许可的本地安全控制，而非无限沿用旧令。
- 权限撤回应传播到网关和执行端；仅在中心数据库撤销而现场缓存仍可执行是危险的 TOCTOU 缺陷。
- kernel 必须提供强身份、能力范围、双批准、租约/撤销、命令签名和策略决策审计。
- 应用/组织层必须定义调度权归属、设备操作规程、CIP 合规映射与紧急授权的法律责任。

## 对通用 agent kernel 的能力结论

### kernel 必须提供（最小而有力的能力）

- 以版本化恢复计划表示任务 DAG、硬前置条件、人工门控、替代分支和禁止并行关系。
- 面向长时物理操作的持久化 workflow：幂等命令、外部回执、观测验证、超时、补偿和可恢复执行。
- 资源租约/容量预留/冲突锁，且支持按孤岛、走廊、设备与控制权建模。
- 状态模型必须原生保留来源、质量、观测/接收时间、置信度、版本和 `unknown/stale`，并可执行新鲜度门控。
- 分层授权：身份、能力、两方批准、短租约、可传播撤销和审计；执行端必须能验证命令授权。
- 分区容忍：本地自治计划、离线命令队列、冲突安全的重连对账，而非假装全局强一致一直可得。
- 人在环接口：审批、复诵、现场见证、升级路由和结构化班次交接。
- 可靠审计：不可变事件、相关 ID、决策依据、时间不确定度和可导出的因果追踪。
- 明确的安全策略钩子：kernel 负责“未通过门禁不得执行”，应用提供“门禁的电力规则”。
- 将硬实时控制隔离在 kernel 外，并提供对其状态/告警的只读事件接入而非调度延迟承诺。

### 注定属于应用层、kernel 不应管理

- 具体黑启动机组名单、燃料状态、厂用电路径、输电拓扑和各地区恢复预案。
- 潮流、短路、暂态稳定、无功优化、状态估计、继保配合及其模型参数。
- 频率/电压/相角阈值和保护动作；它们须由电力工程规程和本地硬实时设备执行。
- 关键负荷优先级、跨区政治/合同协调、调度权法律责任和紧急操作规则。
- IEC 61850/DNP3 等协议的细节适配、设备点表、供应商互操作性和现场网络改造。
- 人员培训、演练设计、工作票/安全隔离和对物理损坏的抢修处置。

## 开发者最头疼的三件事

1. **在不完整、互相矛盾且会陈旧的遥测下做正确动作。** 设备命令可能已经作用于物理系统但回执丢失；错误地把未知当作失败并重试，比停住等待更危险。
2. **把严格依赖、连续物理约束和跨组织权责放入同一个恢复编排。** 普通 DAG 不理解频率/无功余量、并网同步和“谁有权下令”，一个看似并行优化会造成级联失稳。
3. **在 SCADA/通信/控制中心部分失效时保持可控、可接管、可追责。** 既要让本地孤岛存活，又要防止双主控制、陈旧授权和恢复后状态错账。

## 结论：kernel 与前端的边界

- kernel 应替开发者扛掉跨系统工作流的耐久性、权限租约、证据门控、状态质量、失败编排、离线对账和审计这些重复且容易出错的“协作底盘”。
- kernel 应暴露有限接口：注册能力/资源、提交版本化计划、报告有质量的观测、申请/批准/撤销命令租约、推进/暂停/接管任务、查询可审计状态。
- 前端应展示恢复图、孤岛/资源/状态质量、审批队列、冲突和时间线；前端不能直接成为绕过 kernel 授权的控制通道。
- 电网应用应将工程模型和规程编译为门控策略/执行器，且保有对实际控制协议和硬实时安全设备的最终责任。
- 因此合适的协调模式是一句：**预案驱动的层级指挥 + 带证据门的收敛恢复循环 + 分区时的本地安全自治。**
